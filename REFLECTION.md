# REFLECTION.md - Analisis Kritis TaskMate

## (a) Kelemahan Arsitektur Jika Aplikasi Berkembang 10x Fitur

Arsitektur TaskMate saat ini sudah cukup rapi untuk skala UTS dan prototype karena menggunakan Expo Router, pemisahan folder `app`, `src/context`, `src/components`, `src/hooks`, `src/services`, dan `src/constants`. Namun jika fitur berkembang 10x, misalnya terdapat modul project, komentar, notifikasi, role permission, file attachment, analytics, audit log, dan realtime chat, kelemahan utama akan muncul pada pemisahan domain. Saat ini state task masih terpusat pada satu `TaskContext`, sehingga semakin banyak fitur akan membuat context menjadi besar, sulit dites, dan berpotensi menyebabkan re-render berlebihan. Struktur route juga masih sederhana, sehingga jika banyak nested screen ditambahkan tanpa grouping domain, navigasi akan sulit dipelihara.

Perbaikan yang feasible adalah menerapkan feature-based architecture seperti `src/features/tasks`, `src/features/auth`, `src/features/projects`, dan `src/features/notifications`. Setiap feature memiliki screen, component, hook, service, type, dan store sendiri. Untuk skenario 10x fitur, data fetching sebaiknya dipindah ke layer khusus seperti React Query atau TanStack Query agar caching, retry, pagination, dan invalidation lebih terkendali. Komponen UI umum seperti Button, Input, Card, dan Badge sebaiknya distandarkan dalam `src/components/ui` supaya konsisten.

## (b) Restrukturisasi State Management Jika Tim Bertambah 5 Developer

Jika tim bertambah menjadi 5 developer, Context API + useReducer masih dapat dipakai untuk modul kecil, tetapi perlu batas kepemilikan yang jelas. Satu context global untuk semua data tidak ideal karena conflict merge akan sering terjadi dan tanggung jawab kode tidak jelas. Restrukturisasi yang disarankan adalah membagi state berdasarkan domain: `AuthProvider`, `TaskProvider`, `ProjectProvider`, dan `NotificationProvider`. Setiap provider hanya mengelola state domainnya sendiri dengan action type yang konsisten.

Untuk tim lebih besar, penggunaan Redux Toolkit dapat dipertimbangkan jika state antar modul mulai saling bergantung, misalnya task membutuhkan project, user, permission, dan notification dalam satu flow. Redux Toolkit memberi pola standar berupa slice, action, selector, dan middleware. Developer dapat bekerja paralel pada slice berbeda dengan kontrak type yang jelas. Selain itu, perlu dibuat aturan kolaborasi seperti code owner per feature, linting wajib, type checking pada CI, pull request review, conventional commit, dan dokumentasi kontrak API. Selector atau custom hook harus digunakan agar komponen tidak mengakses struktur state mentah secara langsung.

## (c) Security Concern pada API dan AsyncStorage + Solusi

Concern API pertama adalah komunikasi data melalui jaringan. Jika API tidak menggunakan HTTPS, data login, task, dan token dapat disadap melalui man-in-the-middle attack. Solusinya adalah wajib memakai HTTPS TLS modern, certificate pinning untuk aplikasi mobile, dan validasi sertifikat. Concern kedua adalah autentikasi dan otorisasi. API yang hanya mengandalkan client-side validation mudah dimanipulasi. Solusinya adalah validasi token JWT di server, access token berumur pendek, refresh token rotation, dan permission check berbasis role pada setiap endpoint.

Pada AsyncStorage, concern pertama adalah data disimpan plaintext. Jika token atau data sensitif disimpan di AsyncStorage, data bisa dibaca dari device yang sudah compromised. Solusinya adalah tidak menyimpan password/token sensitif di AsyncStorage, tetapi memakai SecureStore, Keychain iOS, atau Keystore Android. Concern kedua adalah integritas data. Data di AsyncStorage dapat dimodifikasi oleh pihak yang memiliki akses device, sehingga status task atau identitas user bisa dipalsukan. Solusinya adalah menjadikan server sebagai source of truth, melakukan validasi ulang di backend, dan memakai checksum/signature jika harus menyimpan data lokal penting. Untuk TaskMate versi produksi, AsyncStorage cukup untuk cache non-sensitif seperti preferensi UI atau daftar task offline, tetapi bukan untuk credential dan data rahasia.
